## 二、P0：生命循环（life loop）

### 2.1 一句话定义

**她现在有没有"活着"的状态，而不是"有没有被触发"。**

### 2.2 四个状态

```
idle       待着（可能在想事，也可能发呆）
talking    跟人说话（最高优先级）
doing      在做一件事（查资料、整理记忆、做任务）
sleeping   睡着（作息 / 小睡）
```

**状态迁移：**

```
idle   --消息-->      talking
talking --聊完-->     idle（或回到 doing）
idle   --想做事-->    doing
doing  --消息-->      talking（doing 进栈）
talking --结束后-->   doing（从栈恢复）或 idle
任何   --睡觉-->      sleeping
sleeping --醒来-->    idle
```

### 2.3 事件队列（inbox）

**所有"发生的事"都进队列，循环按优先级取：**

| 事件类型 | 例子 | 优先级 |
|---|---|---|
| `message` | 有人发消息 | 最高（立即打断） |
| `tool_result` | 工具返回了 | 高 |
| `timer` | 慢循环到点 | 中 |
| `impulse` | 欲望满了、想起一件事 | 低 |
| `user_task` | 你交代的事 | 中高 |

### 2.4 三层计时（省钱的关键）

```
快循环  每 1~3 秒    只处理事件，不调模型          成本 ≈ 0
慢循环  每 3~5 分钟  醒着且没在聊天时，才可能"想一想"（调模型）
深循环  每 1 小时    整理记忆、盘算、处理没做完的事
```

**原则：活着不等于一直在算。人的大部分时间是"在场"，不是"思考"。**

### 2.5 打断与恢复（最像人的一点）

**被打断时必须存下：**

```
· 我在做什么（一句话）
· 做到第几步 / 下一步要干什么
· 用到了哪些工具、结果是什么
```

**存到 `.data/life.json`：**

```json
{
  "state": "talking",
  "activity": {
    "what": "在整理昨天的记忆",
    "step": 2,
    "next": "把第 2 条整合重新压一遍",
    "startedAt": 0,
    "pausedAt": 0
  },
  "stack": []
}
```

**聊完之后她可以说："刚才我在弄记忆，弄到一半——要接着弄吗？"** **（这就是"活着"和"被调用"的区别。）**

### 2.6 闲时想什么（不烧钱清单）

```
回想    从记忆里挑几条最近没提起的，串一下        纯计算
盘算    看任务表里有没有没做完的                  纯读文件
发呆    把最近话题转一圈（低频、便宜的模型调用）   可选
身体    心情/精力自然衰减与恢复                    纯计算
```

**只有"盘算出结果且她真想动"时，才花一次完整模型调用。**

### 2.7 预算与刹车

```
每小时最多  10 步（一步 = 一次模型调用或一次工具调用）
每天最多    N 次模型调用（可配）
连续空转    同一件事想 3 次没进展 → 放下，写日志
夜间        睡着期间不调模型（除非有人叫）
```

### 2.8 可观察（面板）

```
· 她现在在做什么（state + activity）
· 今天想了多少次、做了几件事
· 被打断过几次、恢复了没有
· 预算用了多少
```

**面板要能回答："她刚才在干嘛？"**

### 2.9 文件与模块

```
新增  src/core/lifeloop.js     状态机 + 事件队列 + 三层计时
新增  src/core/inbox.js        事件队列（可持久化）
新增  .data/life.json          当前状态 + 被打断的栈
新增  .data/tasks.json         待办（她自己记的 + 你交代的）
改造  scheduler/               降级为"慢循环的一个输入"
改造  autonomy.js              降级为"冲动来源之一"
```

### 2.10 验收标准

```
① 你插话，她 3 秒内响应（不等 5 秒静默窗口）
② 聊完她说得出"刚才在做什么"
③ 没有消息的一小时里，她做了 0~2 件事（不是 0 件，也不是 10 件）
④ 重启后，life.json 能恢复"她在做什么"
⑤ 一整天模型调用次数在预算内
```

## 三、P1：桌面感知（只看，不动）

### 3.1 为什么改

```
现在  capture_screen 一次截整屏（2560×1600）
      里面有微信、密码框、别的窗口
      隐私风险 + 她抓不住重点
```

### 3.2 改成两步

```
第一步  只给窗口标题列表（不截图）
        list_windows → ["QQ", "Chrome - GitHub", "记事本 - 未命名"]

第二步  她说要看哪个，才截那个
        capture_window("QQ") → 只截那块

第三步  她自己看（look_at_image，屏幕模式，最多 500 字）
```

### 3.3 三道闸

```
① 默认不截屏：只有她主动要才截
② 敏感窗口永不给：密码管理器、银行、隐私浏览
③ 每次截图写日志：截了哪个窗口、几点、为什么
```

### 3.4 读图质量（已改好，保留）

```
表情包  15 字，只说情绪
照片    40 字，说人物+文字
屏幕    最多 500 字，要求：窗口标题 / 主要内容 / 文字按位置念 / 控件位置
        支持附加提问（question 参数）
```

### 3.5 验收标准

```
① 她要截图前，先列窗口（日志里能看到 list_windows）
② 截图只包含她点名的窗口
③ 敏感窗口在黑名单里，调了会被拒
④ 她能说清"这个窗口里写了什么"
```

## 四、P2：桌面操作（只在虚拟机里）

### 4.1 为什么必须隔离

```
桌面操作 = 给一个 AI 你的鼠标键盘
她可能点错、可能误删、可能把确认框点掉
真机：错了就是错了
虚拟机：快照回滚
```

### 4.2 方案对比

| | 虚拟机（Hyper-V / VirtualBox） | 另一台旧电脑 |
|---|---|---|
| 恢复 | 一键快照 | 重装/手动 |
| 成本 | 免费 | 机器 + 电费 |
| QQ 登录 | 有异地风险 | 同样 |
| 网络 | 走宿主，简单 | 要组网 |
| 适合 | 试验期 | 长期 7×24 |

**推荐：她的"大脑 + QQ"留在本机（稳定），桌面操作放虚拟机。**

### 4.3 技术要点

```
· 虚拟机里装 Windows-MCP Server
· 我们的 MCP 客户端现在只支持 stdio → 需要加 SSE/HTTP 传输
· 虚拟机内 MCP 监听 127.0.0.1，通过宿主端口转发访问
· 操作前自动快照（可选，每天一次）
```

### 4.4 权限分级

```
默认开：capture_* / list_* / ocr_* / mouse_position
第二批：click / double_click / type_text / press_key / scroll
不开：  kill_process / execute_sequence
```

### 4.5 硬规则（写在提示词里，不是硬拦）

```
· 点"删除/发送/付款/确认"之前，先停下来问一句
· 不碰密码框
· 一次只做一步，做完报告结果
```

### 4.6 验收标准

```
① 虚拟机快照能回滚
② 她能打开记事本、输入一行字、保存（全在虚拟机里）
③ 真机文件系统不受影响（验证：真机某个文件未被改动）
④ 每一步都有日志
```

## 六、风险清单

| 风险 | 后果 | 兜底 |
|---|---|---|
| 生命循环空转 | 烧钱、日志爆炸 | 预算 + 连续空转刹车 |
| 她打断后忘记原任务 | 像没记性 | life.json 持久化 + 恢复提示词 |

| 桌面误操作 | 删文件、发错消息 | 只在虚拟机 + 破坏性操作先问 |

| 模型工具调用残渣 | 聊天里出现 `<parameter>` | 已有 `#stripToolMarkup` 清理 |
